# 第一步：60 分钟让方块跑起来、跳起来

> 目标只有一个：**一个纯色方块能左右跑、按空格跳上平台、松开跳键跳得矮**。
> 不碰美术、UI、射击、敌人、词条、Shader、相机跟随。
> 环境：Unity 6.3 LTS 或团结引擎（Unity 2022.3 分支）均可，2D 模板；脚本已用版本宏自动适配 `velocity` / `linearVelocity`。代码用旧 Input Manager，若报输入异常需把 Active Input Handling 设为 Both。

## 文件怎么放

把 `Assets/Scripts/` 里的 4 个 `.cs` 复制到你的 Unity 项目同名目录；把 `.gitignore` 放到项目根目录。
本目录**不是**可直接打开的 Unity 项目（没有 ProjectSettings），只是脚本与配置模板。

| 文件 | 作用 |
| --- | --- |
| `InputReader.cs` | 每帧采集输入意图，不施加物理 |
| `PlayerStats.cs` | 参数资产（ScriptableObject），手感数值集中管理 |
| `PlayerMotor.cs` | 非对称重力、土狼时间、跳跃缓冲、松键截断、水平加速度 |
| `TuningPanel.cs` | 可选，运行时滑块实时改参数 |
| `.gitignore` | Unity 专用，忽略 Library/ 等，但**不忽略 .meta** |

## 步骤 0 · 装环境与 Git（10 min）

1. Unity Hub 安装 **Unity 6.3 LTS**，新建项目选 **2D (Core / Built-in)** 模板，命名如 `RogueliteShooter`。
2. 项目根目录执行：

```bash
git init
git add .
git commit -m "chore: init Unity 2D project"
```

先把 `.gitignore` 放进去再 `git add`，否则 `Library/` 会被提交进去。

3. **必做设置**：`Edit → Project Settings → Player → Other Settings → Active Input Handling` 改成 **Both**（或 `Input Manager (Old)`）。
   Unity 6 新项目默认只启用新 Input System，用 `Input.GetAxisRaw` 会抛 `InvalidOperationException`。等 W2 再考虑迁到新 Input System。

## 更快的方式：一键生成灰盒（推荐）

把 `Assets/Editor/StarterSceneBuilder.cs` 一起复制进项目（**目录名必须是 `Editor`**，Unity 才会把它当编辑器脚本编译）。等编译完成后点菜单：

**Tools → Build Starter Scene**

它会自动完成：生成白色方块贴图 → 创建 `PlayerStats.asset` → 建正交相机 → 搭 3 个阶梯平台 → 创建玩家并挂好 `Rigidbody2D` / `BoxCollider2D` / `InputReader` / `PlayerMotor` / `TuningPanel`，连 `[SerializeField]` 私有字段引用都自动填好 → 保存为 `Assets/Scenes/StarterScene.unity`。

然后直接按 Play 即可，手动拖拽全跳过。下面的手动步骤仍然值得看一遍，用来理解每个部件是怎么来的。

## 步骤 1 · 搭灰盒场景（20 min）

1. `GameObject → 2D Object → Sprites → Square`，命名 `Player`，位置 `(0, 0, 0)`，保持 1×1 大小。
2. 给 `Player` 加 `Rigidbody2D`（Body Type = Dynamic）和 `BoxCollider2D`。
   脚本会在 `Awake` 里自动设 `gravityScale = 0`、`freezeRotation = true`、`interpolation = Interpolate`，无需手填。
3. 再建 3 个 Square，命名 `Platform_A/B/C`，每个都加 `BoxCollider2D`，摆成阶梯：

| 对象 | Position | Scale |
| --- | --- | --- |
| Platform_A | `(-3, -2, 0)` | `(4, 0.5, 1)` |
| Platform_B | `(0, -1.2, 0)` | `(2, 0.5, 1)` |
| Platform_C | `(3, -0.4, 0)` | `(2, 0.5, 1)` |

4. 选中 Main Camera，把位置调到 `(0, 0, -10)` 左右，Size 调到 6，确保三个平台都在视野里。

## 步骤 2 · 挂脚本与参数资产（15 min）

1. 复制 4 个 `.cs` 到 `Assets/Scripts/`，等 Unity 编译完成（右下角转圈结束）。
2. 在 Project 面板右键 → `Create → Game → Player Stats`，命名 `PlayerStats`。
3. 选中 `Player` 对象，`Add Component` 依次挂上 `InputReader`、`PlayerMotor`；把 `PlayerStats` 资产拖到 `PlayerMotor` 的 **Stats** 字段，把 `InputReader` 组件所在对象拖到 **Input** 字段（同一对象时可直接拖自身）。
4. 可选：再挂 `TuningPanel`，同样把 `PlayerStats` 拖进 **Stats**。

`PlayerMotor` 会在 `Awake` 里自动在玩家脚下创建一个 `GroundCheck` 空物体，无需手动创建。默认检测盒在 `y = -0.5`（对应 1×1 方块），若你改了方块尺寸，调 `Ground Check Offset`。

## 步骤 3 · 按 Play，验证四件事（15 min）

| 操作 | 预期 |
| --- | --- |
| A / D 或 ← / → | 方块左右移动，松键后很快停下 |
| 按住 Space | 跳上更高的平台 |
| **轻点 Space 立刻松开** | 明显跳得矮（松键截断生效） |
| 走出平台边缘后马上按 Space | 仍能跳起来（土狼时间生效） |
| 落地前提前按一下 Space | 落地瞬间自动起跳（跳跃缓冲生效） |

挂了 `TuningPanel` 的话，运行时拖「跳跃高度」「到顶时间」「下落重力倍率」三个滑块，观察手感变化，并记下哪一组最舒服。面板会实时显示反推出来的 `v0 / gUp / gDown`。

## 步骤 4 · 反过来学（跑通之后，每题 10 分钟）

带着**你自己正在跑的代码**去查官方文档，比先啃教程有效得多：

1. `Update` 和 `FixedUpdate` 为什么分工？为什么计时在 `Update`、施加速度在 `FixedUpdate`？
2. `Rigidbody2D.linearVelocity`（Unity 6；旧版是 `velocity`）与 `AddForce` 的区别？为什么脚本把 `gravityScale` 设为 0 自己算重力？
3. `ScriptableObject` 为什么比在 MonoBehaviour 里写一堆 `public float` 好？（提示：多对象共享、运行时可调、不随场景重置）
4. `Physics2D.OverlapBoxAll` 为什么要排除 `hit.attachedRigidbody == rb`？正式项目里为什么不这么写而要用 Ground Layer + LayerMask？

把答案写成 4 段短笔记放进 `Docs/notes.md`，这是第一篇技术复盘的材料。

## 常见问题

| 现象 | 原因 |
| --- | --- |
| `InvalidOperationException: You are trying to read input using the UnityEngine.Input class` | Active Input Handling 没设成 Both |
| 方块一直往下掉 | 平台忘了加 `BoxCollider2D` |
| 按 Space 没反应 | `Stats` 资产没拖进字段；或 `GroundCheck` 的 `y = -0.5` 与方块尺寸不匹配 |
| 一直能跳（像二段跳） | 检查 `coyoteTimer = 0f` 那行是否被删了 |
| 场景里看不到方块，只有一个空框 | 团结引擎的 Sprite PPU 默认 100，1×1 贴图只有 0.01 单位；脚本已改为生成 100×100 贴图（=1 单位），重新点 `Tools → Build Starter Scene` 即可 |
| Unity 2022 / 团结引擎分支 | 脚本已用 `#if UNITY_6000_0_OR_NEWER` 自动切换 `linearVelocity` / `velocity`，无需手改 |
| 参数调完退出 Play 就还原 | ScriptableObject 资产在编辑器里改动会保留；若用代码 `Instantiate` 副本则不会，先不要这么做 |

## 设计说明（面试可讲）

- `PlayerStats` 只存「跳多高、多久到顶」，`JumpVelocity = 2h/t`、`GravityUp = v0/t` 由代码反推，避免手填两个互相矛盾的数。
- 下落重力 = 上升重力 × 1.6，落地更干脆（见配套设计文档的曲线对比）。
- 输入意图与物理解耦：`InputReader` 用 `[DefaultExecutionOrder(-100)]` 保证先采集，`PlayerMotor` 在 `Update` 判断、在 `FixedUpdate` 施加。
- 所有计时用 `Time.deltaTime` / `Time.fixedDeltaTime`，与帧率无关。

## W2：射击与战斗反馈（W1 跑通后接着做）

菜单 **`Tools → Build W2 Scene`** 会在 W1 灰盒上加一个红色敌人、给玩家挂 `Weapon`、给相机挂 `HitFeedback`，另存为 `Assets/Scenes/W2Scene.unity`。

按 Play 后：**鼠标指向敌人，按 `J` 或鼠标左键开火**。验证：子弹飞出、命中时敌人闪白并被推开、屏幕抖一下且有短暂停顿、3 发后敌人消失；连续射击时 Profiler 无 GC 尖峰。

## W3：肉鸽最小闭环（W2 跑通后接着做）

新增 `RunStats.cs`（**struct** 运行时数值，避免 C# 引用拷贝污染基础值）、`Modifier.cs`（8 个词条的数据表，只描述改哪个字段 / 怎么改 / 最多叠几层）、`RunManager.cs`（seed、3 波敌人、清怪判定、三选一 UI、结算与重开）。同时让 `Weapon` 从 `RunStats` 读射速与子弹数、`Enemy` 死亡时通知 `RunManager`。

菜单 **`Tools → Build W3 Scene`** 生成 `W3Scene.unity`。按 Play 后：清完 2 个敌人 → 三选一 → 下一波（3 个）→ 三选一 → 第 3 波（4 个）→ 结算页显示用时、击杀、seed 和本局词条，可「同 seed 重玩」或「开新的一局」。

**关键点**：所有随机都走同一个 `System.Random(seed)`，不混用 `UnityEngine.Random`；词条只改 `RunStats` 数据，战斗代码一行不改；`maxStacks` 防止叠加爆炸。在 `RunManager` 的 Inspector 里把 `Seed Override` 填非 0 即可固定复现。

已知局限（写进复盘）：W3 用「波次」代表房间，敌人是悬浮靶子、没有 AI 与地形逻辑；词条全是正面增益，还没有取舍设计；词条表暂用代码静态表，W4 可迁到 ScriptableObject 资产。

## W5：血量 / 失败结算 / 随机地图与怪物

新增 `PlayerHealth.cs`（5 血、0.8 秒无敌帧、受伤闪烁、归零触发失败）、`EnemyBullet.cs`（敌人定时朝玩家发射的慢速子弹）；改 `Enemy.cs`（按 seed 随机出的血量 / 体型 / 颜色 / 射速 + 定时开火）、改 `RunManager.cs`（每局随机 2~4 块悬浮平台、敌人随机位置且离玩家 ≥2.5 单位、三类怪物、HUD 增加 HP、结算分「通关 / 阵亡」）。

三类怪物：普通 55%（红、标准血、2.2 秒一发）、快速 30%（橙、血少、1.2 秒一发）、精英 15%（紫、血厚体型大、2.8 秒一发）。

**随机与复现**：平台布局、敌人位置 / 类型 / 首发延迟、三选一全部消费同一个 `System.Random(seed)` 实例。在结算页点「重玩本局」，两次第一波的敌人颜色、位置、地图应完全一致。

## W6：打击感与活力（敌人移动 / 粒子 / 音效）

新增 `GameAudio.cs`：用 `AudioClip.Create` **程序合成 7 种音效**（开火、命中、受伤、升级、波次、胜利、失败），滑音做出上升 / 下降情绪；**按 M 静音**；静态 `Play` 懒加载自己，旧场景无需挂载。新增 `HitParticles.cs`：运行时生成小方块飞散淡出，方向用「索引 + 命中位置」的确定性伪随机，**刻意不用 `UnityEngine.Random`**，避免破坏 seed 可复现。

`Enemy` 现在会缓慢朝玩家水平靠近（保持 2.5 单位不贴脸）、上下正弦浮动；速度按类型区分（快速 1.6 / 普通 0.8 / 精英 0.45），由射速推断，不改 `RunManager` 接口。击杀爆 9 个粒子；`Bullet` 命中出 4 个黄色粒子 + 命中音；`PlayerHealth` 受伤出 6 个红色粒子 + 受伤音；选词条 / 通关 / 阵亡各有提示音。

**关键点**：视觉与听觉反馈全部纯代码生成，不依赖任何外部美术 / 音频资源，WebGL 打包不会丢资源。

已知局限：音效是合成正弦波，偏"电子"没有真实采样；粒子用 `Destroy` 未池化；敌人移动只是靠近 + 浮动，没有寻路、避障或攻击预警。

## W7：打击反馈重做 / 暂停与设置 / 掉落保护 / 记录

**上一版的震动是错的**，问题不在"有点强"，而在设计：每发子弹命中都触发 0.12 单位随机跳变 + 全局 `timeScale = 0`。6 发/秒时等于每秒十几次地震叠加十几次卡顿。

`HitFeedback` 整体重做：
- 分三级 `Feel.Hit / Kill / Hurt`：震幅 0.020 / 0.045 / 0.070，**普通命中不再触发命中停顿**（停顿只给击杀 0.035s 与受伤 0.055s）
- 0.05 秒内的连续命中**合并取最大值**，绝不线性叠加
- 抖动按剩余时间**二次衰减**，尾巴更顺，不再是生硬的随机跳
- 整体乘以 `GameSettings.ShakeScale`，玩家可在暂停菜单里切成「关 / 弱 / 标准 / 强」，默认**弱**

新增 `GameSettings.cs`：PlayerPrefs 持久化震屏档位、音量、最高击杀数、最快通关时间；`GameAudio` 音量改为读它并在设置里实时生效。

新增 `PauseMenu.cs`：**Esc** 暂停 → 继续 / 画面震动档位 / 音量 ± / 重开本局（同 seed）/ 返回标题。`timeScale = 0` 同时暂停音频；`Weapon` 单独拦了暂停输入（否则 deltaTime = 0 会让冷却卡住却仍能开火）。只在 `Playing` 阶段响应，三选一 / 结算时不会误弹。

`PlayerHealth` 新增**掉落保护**：低于 `y = -7` 自动送回出生点并扣 1 血，不再是无限下坠；重开一局时也会归位。

`RunManager` 新增 `RestartCurrent()` / `ReturnToTitle()`，结算时调用 `GameSettings.SubmitRun()` 入档；标题页显示历史最佳。

配套文档：`roguelite-platform-shooter-plan.md`（完整项目设计）、`cpp-to-csharp-accelerated-path.md`（有 C++ 基础的 5 周路线）、`GAME-COMPLETION-ROADMAP.md`（把 demo 做到「完成」的阶段计划）。

## W8：失败解释 / 波次补给 / 难度曲线 / 快速重开（v0.5）

这一版的目的不是加内容，而是让**一次失败变得可理解**。

- **结算页说清为什么输**：新增三个统计——`shotsFired` / `shotsHit`（命中率）、`damageTaken`（挨了多少点）、`lastDamageSource`（最后一击来自谁）。为此 `Weapon` 上报开火数（按子弹数，散射算多发）、`Bullet` 上报命中、`EnemyBullet` 携带发射者类型（普通/快速/精英怪）、`PlayerHealth.TakeDamage(amount, source)` 上报归因。结算页显示：命中率 xx%（命中/发射）、受伤 n 点、最后一击来自「精英怪」/「掉出平台」。
- **波次间补给**：选完词条回 1 血（`PlayerHealth.Heal`），避免一局打到中段就彻底无解；满血时不浪费。
- **难度曲线改成表驱动**：`WaveCount / WaveHp / WaveNormal / WaveFast` 四张表。第 1 波 2 个纯普通怪练手，第 2 波 3 个（65% 普通 + 35% 快速），第 3 波 4 个（45 / 30 / 25 含精英）。**类型权重按波次递进，而不是一开始就三分天下**——上一版第 1 波就可能出精英，新手第一分钟就被劝退。
- **快速重开**：结算页按 `R` 立刻重开本局（同 seed）；标题页空格 / 回车直接开局。失败到再开一局从 2 次点击降到 0 次。

**注意**：难度表的 `rng.Next(100)` 仍然每只怪只消耗一次随机数，随机消费顺序没变，所以旧 seed 依然能复现（只是敌人构成会跟旧版本不同）。

## W10：单一大房间 / 每波回中央 / 敌人飞入（v0.7）

### 1. 场地改成一间封闭的大房间

`BuildLevel()` 换成 `BuildRoom()`：

- **一整块地板**，宽 26、厚 1.2，中心在 `y = -2.6`（台面 `-2.0`）。26 宽超出相机视野（16:9 时 halfWidth ≈ 10.7），所以**看不到地板边缘**。
- 左右各放一个**不可见边界**：只有 `BoxCollider2D`（0.2 × 40），没有 `SpriteRenderer`。玩家撞上去会停住，但屏幕上没有任何"墙"。
- 悬浮平台 2~4 块随机，台面离地 2.0~3.0，跳跃高度 3.2 够得着。

两个取舍值得记：

- **为什么不用看得见的墙**：墙会挡住"从房间边缘飞入"的敌人（敌人是手动位移，穿墙而过会穿帮）。不可见边界没有这个问题。
- **为什么边界只有 0.2 厚**：`PlayerMotor` 的落地检测是 `OverlapBoxAll` + `groundMask = ~0`，会把任何碰撞体当成地面。边界如果做得厚，玩家贴墙站着就能"踩"到边界变成 grounded，甚至能贴墙多跳一次。0.2 厚 + 放在 ±8.2，玩家中心最多到 7.9，落地框（±0.3）碰不到 8.1 起的边界。

地面兜底还在：`y < -7` 依然送回出生点并扣 1 血，但现在正常玩碰不到。

### 2. 每波开始回到房间正中

> W11 已改为「每关在随机位置出生」，本节只记录当时的做法。

`Pick()` 里在进入下一波前调用 `PlayerHealth.RespawnAtSpawn()`（传送 + 清速度），再回 1 血。

这也顺带解决了一个隐藏问题：之前玩家可能站在悬浮平台边缘或贴着墙进入下一波，新怪从侧面飞进来会直接贴脸。现在每波都从中心、面向开阔地开始。

### 3. 敌人从房间两侧飞入

`Enemy.PlayIntro(target, from, duration, delay)`：

- 出生点直接放在目标站位，`Init()` 先把 `baseY` 记好，再挪到房间外（`±(8.2 + 3.3)`）
- **延迟** `0.07 * index` 逐个进场，不是一排同时飞
- 飞行 0.55 秒，ease-out + `sin(πk) * 0.35` 的上抛弧线，落位有重量
- 飞行期间 **碰撞体关闭**（不可被击中）、**不执行行为**（不射击、不撞人）、延迟期间连 Sprite 都关掉
- 落地那一帧打开碰撞、爆 4 个同色粒子作为"显形"

实现上有个顺序陷阱：`kind` 必须在 `Init()` 之前赋值（决定 `moveSpeed`），而 `PlayIntro()` 必须在 `Init()` 之后调用（`Init` 会用当前位置记 `baseY`，先飞出去就会把 `baseY` 记成房间外的坐标，之后整只怪会飘在屏幕外）。

已知局限：入场是"直线插值 + 垂直弧线"，没有真正的路径规划；同一波内所有怪从最近的一侧进，视觉上偶尔会一左一右同时涌入。

## W12：进场冻结程序 + 三次缓出曲线 + 时长 1.1~1.7s

> ⚠️ **这一版的"冻结"是用 `Time.timeScale = 0` 做的，已被 W13 推翻**——Unity 会把 `timeScale = 0` 视为编辑器暂停，工具栏暂停键亮起、Game 视图失焦，每次进场都得重新点一下。下面的代码只作为"踩过的坑"保留，实际实现见 W13。

### 1. 新关卡直接冻结整个程序

`StartWave()` 不再直接刷怪，而是起一个协程 `SpawnSequence(duration)`：

```csharp
spawnLockUntil = Time.unscaledTime + duration;
Time.timeScale = 0f;
SpawnRoom();
yield return new WaitForSecondsRealtime(duration);
if (!PauseMenu.IsPaused) Time.timeScale = 1f;
```

冻结的是整个模拟：物理、子弹、粒子、敌人行为全部停住，只有进场动画继续。要做到这点有两个关键：

- **`IsSpawning` 必须用 `Time.unscaledTime`**。原来用的是 `Time.time`，而 `timeScale = 0` 时 `Time.time` 不再前进，锁永远解不开——这是个会直接卡死的坑。
- **协程必须用 `WaitForSecondsRealtime`**。`WaitForSeconds` 在 `timeScale = 0` 时永远不返回。

### 2. 入场动画走 unscaled 时间

`Enemy` 的 `introDelay` 与 `introTime` 都改用 `Time.unscaledDeltaTime`，否则动画会跟着程序一起冻住。

### 3. 速度曲线：三次 ease-out

```csharp
float ease = 1f - Mathf.Pow(1f - k, 3f);
```

二次缓出在起步阶段的初速还不够猛，现在是**三次缓出**：`k = 0.1` 时已经走完约 27% 的距离，`k = 0.9` 时只再挪最后 0.1%。观感是"从边上几乎是冲进来的，快到站位时急收"，配合 `sin(πk) * 0.3` 的上抛弧线。

### 4. 飞行时长 1.1~1.7 秒

`introDur = Mathf.Lerp(1.1f, 1.7f, rng.NextDouble())`，每只都不同；彼此仍错开 0.12 秒。冻结总时长取"最后一只的 延迟 + 飞行"，保证最后一只一定落地后才恢复。

### 5. 连带要改的四处（都容易漏）

程序被全局冻结时，凡是"自己改 `timeScale`"或"在时间静止时仍读输入"的地方都会打架：

| 位置 | 问题 | 处理 |
| --- | --- | --- |
| `PauseMenu.Resume()` | 暂停中恢复会把 `timeScale` 还原成 1，提前解冻 | `Time.timeScale = RunManager.IsSpawning ? 0f : 1f` |
| `HitFeedback` 命中停顿 | 停顿协程结束时会写回 1 | 加 `!RunManager.IsSpawning` 判断 |
| `Weapon` | 冷却因 `deltaTime = 0` 卡住，但输入仍触发 → 子弹停在枪口 | 进场期间直接 return |
| `RunManager.BeginRun / ReturnToTitle` | 重开或返回标题时旧协程还在等，会在错误的时机解冻 | 保存 `spawnRoutine` 句柄并 `StopCoroutine`，`OnDestroy` 兜底把 `timeScale` 复位 |

已知局限：冻结期间粒子与抖动都停住（这是"暂停"的预期行为）；如果以后加背景音乐，需要让它继续播（AudioSource 不受 `timeScale` 影响，但要确认没被 `AudioListener.pause` 带停）。

## W13：放弃 timeScale，改成"只冻结自己的系统"

**问题**：W12 用 `Time.timeScale = 0` 冻结，Unity 编辑器会同步把工具栏的暂停键点亮、Game 视图变成 "Play Unfocused"。每次新关卡都要手动点回 Game 视图才能继续操作，体验很差。

**结论**：`timeScale` 是编辑器共享的状态，不该拿来当游戏内的"某一阶段冻结"。改成**只停我们自己写的东西**，`timeScale` 永远保持 1：

| 系统 | 冻结方式 |
| --- | --- |
| 玩家移动/跳跃 | `PlayerMotor` 里 `IsSpawning` 时清零速度并清空跳跃缓冲 |
| 玩家开火 | `Weapon` 里 `IsSpawning` 直接 return |
| 敌人行为 | `Enemy` 落地后若 `IsSpawning` 直接 return（入场动画分支在它之前，不受影响） |
| 玩家子弹 | `Bullet.Update` 里 `IsSpawning` 直接 return（避免上一波残留子弹打到刚落地的怪） |
| 敌方子弹 | `EnemyBullet.Update` 同样 return |

状态管理也简化了：`spawning` 布尔 + `spawnTimer` 倒计时，在 `RunManager.Update` 里用 `Time.deltaTime` 递减。**用缩放时间的好处是：暂停菜单一按 `timeScale = 0`，进场倒计时和入场动画会跟着停住**，恢复时继续，不会出现"暂停期间敌人偷偷到位"。

`Enemy` 的入场计时因此也回到 `Time.deltaTime`（W12 改成 unscaled 是因为当时整体被冻住，现在不需要了）。

**代价**：粒子、相机抖动这些没被门控的东西仍会继续跑。但它们不影响操作，而且进场时本来就没有战斗，看起来反而自然。

**可迁移的结论**：想"暂停游戏"时优先问一句——是要**停掉模拟**（那就 `timeScale`，接受编辑器的行为），还是要**停掉某段玩法**（那就门控自己的系统）。混用会得到一堆难查的时序 bug；这次还额外踩了"编辑器 UI 与运行时状态耦合"的坑。

## W14：彻底清掉 timeScale=0 + Boss 战

### 1. "还是会暂停"的三个来源，逐个掐掉

查了 `Editor.log`，抓到的证据是：

```
NullReferenceException at RunManager.DrawChoices () [RunManager.cs:632]
```

原因是 `EnsureStyles()` 第一行就把 `stylesReady = true` 置了位，一旦中途抛异常（或脚本处于"字段已加、样式还没加"的中间编译态），就会留下半套 null 样式，之后**每帧**在 `OnGUI` 里刷一次 NRE。修法：

```csharp
private void EnsureStyles()
{
    if (stylesReady) return;
    ... // 所有样式和纹理
    stylesReady = true;      // 必须最后才置位，失败时下一帧能重建
}
```

第二个来源是 `HitFeedback` 的命中停顿还在写 `Time.timeScale = 0f`。改成 **0.05 倍慢放**：

```csharp
private const float HitstopScale = 0.05f;
if (Time.timeScale > HitstopScale) Time.timeScale = HitstopScale;
```

视觉上和完全冻结几乎一样（40ms），但 `timeScale == 0` 才是 Unity 判定"编辑器暂停"的条件，0.05 不会触发。

第三个是兜底看门狗，`RunManager.Update` 里：

```csharp
// 非暂停状态下 timeScale 不允许停在 0
if (!PauseMenu.IsPaused && Time.timeScale == 0f) Time.timeScale = 1f;
```

这样即使以后哪个新系统又写了 0，也会在下一帧被拉回来，不会卡住编辑器。

### 2. Boss 战

Boss 单独做成 `Boss.cs`，**不塞进 `Enemy`**：小怪是"三种行为共用一个状态机"，Boss 是"一条自己的招式循环"，混在一起会让 `Enemy` 变成 if 地狱。两者的清场逻辑也分开——Boss 不进入 `liveEnemies`，死亡时直接回调 `RunManager.BossDefeated()`。

状态机：`Enter → Idle → Telegraph → (Burst | Charge) → Recover → Idle`

| 阶段 | 时长 | 行为 |
| --- | --- | --- |
| Enter | 1.6s | 从房间上方落下 + 缩放 0.5→2.4，碰撞体关闭，不可被打 |
| Idle | 1.1s | 正弦悬停，缓慢漂向玩家 x（1.1 u/s，限位 ±6.2） |
| Telegraph | 0.5s | 颜色在粉/黄之间闪、体型脉冲 8%，**给玩家预警** |
| Burst | 即时 | 朝玩家打 7 发扇形弹幕（每发间隔 0.14 rad），随后 Recover 0.45s |

## W15：三选一 UI 崩溃的真正原因 + 20 条带取舍的词条

### 1. "还是会暂停"其实是"卡在选卡"

日志里的关键一行是 `NullReferenceException at RunManager.DrawChoices`，而且只在你操作时出现（不是每帧刷）。链条是：

```
样式没建好 → DrawChoices 抛异常 → 卡片一张都画不出来
→ phase 停在 Choosing → 玩家被冻结 → 看起来就是"暂停了"
```

`EnsureStyles()` 里 `stylesReady = true` 原来写在第一行，一旦中途抛异常（或 Unity 处于"字段已加、样式还没加"的中间编译态），就会永久留下半套 null 样式，**之后所有帧都跳过重建**。修法三层：

1. `EnsureStyles()` 用 `try/catch` 包住，`stylesReady` **只在成功后置位**，失败下一帧自动重试（并只打一条警告，不刷屏）。
2. `DrawChoices()` 拿不到样式时先强制重建一次，仍失败就**退回默认皮肤**（`GUI.Button(rect, text)` 重载），保证卡片一定画得出来。
3. `OnGUI()` 开头加硬门槛：样式没就绪时只画一行提示，**并且仍然渲染一组纯默认皮肤的选卡按钮**——宁可丑，也不能把玩家锁死在选卡阶段。

顺带一个环境提醒：**UI 只在 Game 视图里绘制**。截图里当前是 `Scene` 标签页，此时看不到 HUD/卡片，很容易误判成"暂停"。

## W16：缺失脚本的诊断工具 + 程序化背景

### 1. "The referenced script is missing" 是什么

Console 里出现 `The referenced script (Unknown) on this Behaviour is missing!` 表示**某个对象上挂着一个找不到脚本的组件**——通常来自：

- 场景里残留了旧脚本的组件（脚本被删/改名/换项目拷贝进来）
- 预制体里引用了不存在的脚本

它和编译错误是两件事：底部显示 `0 errors` 就说明代码是能编译的，游戏也能跑。但它会一直挂在 Console 里，以后真出错时容易被噪声淹没，所以该清掉。

新增 `Assets/Editor/SceneHealth.cs`，两个菜单项：

| 菜单 | 作用 |
| --- | --- |
| `Tools → 诊断 → 列出缺失脚本` | 遍历当前场景所有 GameObject，把带空组件的对象名逐条打到 Console（点日志可高亮对象） |
| `Tools → 诊断 → 清理缺失脚本（当前场景）` | 调 `GameObjectUtility.RemoveMonoBehavioursWithMissingScript` 批量移除，并标记场景为已修改（记得 Ctrl+S） |

实现上只处理 `go.scene.IsValid()` 的对象，避免误伤 Project 里的资源文件。

### 2. 背景：程序生成的渐变

之前场景背景是相机 `SolidColor`，整个画面是一块纯色，观感非常"白盒"。新增 `Backdrop.cs`：

- 生成一张 `1×64` 的竖向渐变纹理（底部偏紫、顶部近黑），`Sprite.Create` 后挂在**相机子物体**上
- `sortingOrder = -100`，永远排在所有游戏对象后面；`localPosition.z = 5` 在相机前方、游戏平面之后
- `LateUpdate` 里按 `orthographicSize × aspect` 重新铺满，改窗口大小也不会露边
- 纯代码生成，不引入任何美术资源

地板颜色同步压暗了一档（`0.30,0.36,0.48` → `0.24,0.27,0.38`），让橙色的玩家和彩色的敌人从背景里跳出来。

**已知局限**：背景是静态渐变，没有视差层；如果以后加相机跟随，需要给 `Backdrop` 加反向位移才像视差。

## W15：不再追"谁暂停了"，改成"任何情况下都不可能卡住"

前四轮都在找"谁把游戏停住了"，每次都能找到一个可疑点，但问题反复出现。这一轮换思路：
**不去证明根因，而是让"卡住"这个结果在结构上无法发生。**

### 找到并修掉的真 bug

`DrawChoices` 里那个 NRE 不是样式问题，是**循环回读了已被清空的 `choices`**：

```csharp
for (int i = 0; i < 3 && i < choices.Count; i++)
{
    ...
    if (clicked) Pick(choices[i]);   // Pick 内部会执行 choices = null
}                                    // 回到 i++ 时再读 choices.Count → NullReferenceException
```

表现就是"卡片能点，点完这一帧 OnGUI 崩掉"，之后 HUD 也不再绘制，看起来和暂停一模一样。
现在改成**先取局部快照、点完立刻 `return`**，同一处模式在 `stylesReady` 兜底分支里也有，一并修掉。

### 彻底不再使用 Time.timeScale

命中停顿原来是 `timeScale = 0.05`。它不是 0，所以不会被当成"编辑器暂停"，
但**只要有一次没还原成功，全局时间就永久卡在 5% 速度**——画面几乎静止，和暂停无法区分，而且我之前的兜底只查 `== 0`，正好漏掉它。
现在删除整个 hitstop 机制，命中重量全部由震屏表达（击杀/受伤振幅上调）。全项目只剩两处把 `timeScale` 写回 1 的兜底。

并且在 `RunManager.Update` 里加了自检：**`Time.timeScale != 1f` 就强制复位并打一条警告**。以后再有任何东西改它，Console 会直接指出来。

### 四个"不可能被锁死"的保险

| 位置 | 保险 | 挡住的死锁 |
| --- | --- | --- |
| `Pick` 之后 | 循环里 `return`，不再回读 `choices` | 选卡时崩掉 → 永远选不了 |
| 选卡阶段 | 12 秒未选择自动拿第 1 项继续 | 卡片没画出来 → 永远停在选卡 |
| 进场冻结 | `spawnElapsed` 绝对上限 4 秒 | `spawnTimer` 异常未赋值 → 玩家永久不能动 |
| 暂停面板 | `stylesReady` 置位移到末尾 + try/catch 退回默认皮肤 | 面板画不出来 → 「继续」按钮也消失 |

另外**三选一不再冻结玩家**：`RunManager.IsControllable` 在 `Playing` 和 `Choosing` 都返回 true，
所以哪怕卡片一张都没画出来，你依然能走动、能开枪——"看起来像暂停"这个误判从此不会出现。
`PauseMenu` 也补了"点面板外也能恢复"，并让 Esc 在三选一阶段也生效。

### 可自证的诊断

- **右上角角标**：`v0.14 · Playing · ts 1.00`。`ts` 不是 1.00 就是时间缩放被动过。
- **阶段日志**：每次阶段切换打一条 `[RunManager] 阶段 → Playing · ts=1.00 · 存活敌人=2`。
  即使你停在 Scene 视图，也能从 Console 看出游戏走到哪一步；**日志不再新增 = 真的停了**。

## W16：房间边界改成看得见的墙，并且贴住画面左右边缘

之前的"边界"是两个不可见的碰撞体，固定在 `x = ±8.2`。问题是相机在 16:9 下正交半宽约 10.7，
所以墙实际位于画面内侧约 2.5 个单位处 —— 玩家会在画面中间被一堵空气墙挡住，既看不见墙，
也说不清为什么走不过去。

### 位置：不再写死，按相机算

```csharp
float halfW = cam.orthographicSize * cam.aspect;   // 16:9 / size 6 → 10.67
boundLeft  = -(halfW - WallVisible);               // 墙内侧面
boundRight =  (halfW - WallVisible);
```

`WallVisible = 0.45`，也就是墙只往画面里露出 0.45 个单位（1920 宽下约 40 px），
剩下 1.4 的厚度全部在画面外，避免宽高比不同时露出缝。**墙的内侧面就是玩家撞到的位置**，
所以"看得见的那条竖条"和"走不过去的地方"完全重合，不会再出现空气墙。

拖窗口 / 改 Game 视图分辨率时，`Update` 里比对 `cam.aspect`，变化超过 0.01 就调用
`RepositionBounds()`：挪墙、拉伸地板、并把被新边界包到外面的玩家拉回房间内。

### 渲染顺序：墙盖住敌人

墙的 `sortingOrder = 20`，比敌人（5）和子弹高。这样敌人从 `boundLeft - 2.2` 起飞时
是**先被墙挡住、再从墙后钻出来**，比之前在空气里凭空滑入自然得多，也顺便把入场路线解释清楚了。

### 必须一起改的落地检测

```csharp
// 只认"顶面在脚边附近"的碰撞体
if (hit.bounds.max.y > groundCheck.position.y + 0.35f) continue;
```

`groundMask` 是 `~0`（Everything），墙一旦变成实体竖直碰撞体，贴着墙站就会"踩"到墙的侧面，
表现为**贴墙可以无限跳**。加上这条过滤后，只有当碰撞体的顶面在脚边附近才算地面；
墙的顶面在 20 个单位高处，自然被排除。平台的顶面就在脚下，不受影响。

已知局限：墙是纯色矩形，没有踢脚线 / 高光之类的细节；如果以后加相机跟随，
墙需要跟着相机移动，`RepositionBounds` 里得把相机 x 偏移算进去。

## W17：程序化背景音乐 + 死亡动画 + Boss 二阶段

这一轮把 P3 打磨里"不依赖任何美术/音频资源就能做的部分"全部做完。

### 1. 背景音乐（`MusicSynth.cs`）

仍然是 `AudioClip.Create`，合成一段 **4 小节无缝循环**：

| 层 | 内容 | 音色 |
| --- | --- | --- |
| 低音 | 每拍一下，根音低八度 | 正弦 + 二次谐波，`Exp(-3.2k)` 衰减 |
| 琶音 | 八分音符，根音/五度/八度/小十度/十二度 | 正弦 + 三次谐波，衰减更快（拨弦感） |
| 底鼓 | 1、3 拍 | 130→45Hz 扫频，`Exp(-7k)` |
| hi-hat | 每拍反面 | 固定种子 LCG 噪声 + 一阶低通 |

和声是 A 小调 **i - VI - III - VII**（Am - F - C - G），104 BPM，总长 9.23 秒。三个细节：

- **接缝**：首尾各 25ms 做淡入淡出，否则循环点会有一下"咔"。
- **软限幅**：四层叠加后个别位置会超过 1，硬截断是刺耳失真，改成 `tanh(1.6x) * 0.92`。
- **噪声用固定种子**：用 `UnityEngine.Random` 的话每次进 Play 的 hi-hat 都不一样，调音色时无法判断是参数起作用还是随机变了。

音乐走独立 `AudioSource`（`loop = true`，音量 `0.20 × Volume`），`RunManager.Awake` 里调 `GameAudio.Ensure()` 让它从标题页就开始放；`M` 静音会同时作用于音效和音乐。

### 2. 死亡动画

**敌人**（`Enemy.UpdateDeath`）：以前是 `SetActive(false)` 直接消失，现在 0.22 秒里先膨胀到 1.35 倍再缩到 0、同时按 `1 - k²` 淡出。三个阶段的关键处理：

- 进死亡状态时立刻 `col.enabled = false`，否则同一帧内多发子弹会重复触发 `NotifyKill`；
- `CancelInvoke(nameof(RestoreColor))`，否则受击闪白 0.08 秒后会把淡出中的颜色刷回基色；
- `NotifyKill` 仍然**立刻**调用（波次要马上推进），然后 `Destroy(gameObject, 0.42f)` 让动画自己播完。

**玩家**（`PlayerHealth.TakeDamage` 的归零分支）：一次 16 颗的爆散 + 二次震动，先让"我死了"在画面上成立，再让结算页盖上来。

### 3. Boss 二阶段

血量过半触发 `Enrage()`：本体换成更红的 `EnragedColor`、爆一圈金色粒子、血条标「狂暴」，之后所有数值通过属性读 `enraged`：

| 冲撞硬直 | 0.70s | 0.45s |
| 冲撞速度 / 漂移速度 | 9 / 1.1 | ×1.2 / ×1.6 |

**只改一处开关**（`enraged` 布尔），不在每个状态里各写一遍 if，避免"改了三处漏了一处"。

顺带把 Boss 移动范围从写死的 `±7.2` 改成 `RunManager.RoomRight`，跟着可见的墙走。

### 4. 每波闪白

## W18：地形挡子弹，以及一批"让它像个完整游戏"的改动

### 1. 平台 / 墙挡子弹（本轮主诉求）

以前子弹只判角色，会直接穿过地板和平台。有两个连带后果：玩家躲在平台后面没有意义，
敌人隔着平台也能打到你——"地形"在战斗里完全不存在。

做法是加一个**空标记组件** `Solid`，挂在所有地形上（地板、墙、悬浮平台），子弹用
`GetComponent<Solid>()` 判断：

```csharp
// 第一遍只认角色，第二遍才认地形
foreach (hit in hits) { if (Enemy/Boss) { 命中; return; } }
foreach (hit in hits) { if (hit.GetComponent<Solid>() != null) { 火花; 回收; return; } }
```

**为什么分两遍、角色优先**：如果同一帧里子弹既压到平台又压到贴着平台边缘的敌人，
先命中敌人，否则玩家会觉得"明明打到了却没反应"。反过来先判地形，站在平台下沿的敌人
就会变成无敌的。

**为什么用组件而不是 LayerMask**：层是项目级配置，而这些地形全是运行时 `new` 出来的，
挂组件不会和用户的层设置冲突，也不会因为新建场景忘记配层而静默失效。

敌方子弹同样会被挡——于是"躲到平台后面"变成了真正的战术，射手怪和炮台不再能穿透射击。
代价是 Boss 的扇形弹幕也会被平台吃掉一部分，实际打起来反而更强调走位和掩体选择。

### 2. 敌人开火前发亮预警

`UpdateFireTelegraph()`：`fireTimer` 进入最后 0.28 秒时，颜色从本体色插值到白色。
没有预警的远程攻击在平台游戏里只能靠背板。受击闪白期间跳过这段（`hitFlashUntil`），
否则"被打中"的白闪会被预警色顶掉。

### 3. 受伤红闪 + 低血量脉动

`DrawEdgeWarning()` 只在屏幕**四条边**上画红色块（不铺满，避免盖住战场）：

- 受伤瞬间 `hurtFlash = 1`，0.45 秒内褪掉，边条厚度 8→30px 随强度变化；
- 剩下 1 血时，边条以 4.2 rad/s 缓慢脉动，提示"再挨一下就没了"。

### 4. 子弹池 16 → 48

满 build（射速 30 × 5 弹丸）在子弹撞墙前最多同时存在 ~70 发，原来 16 个会**静默丢弃**
一半以上的子弹——高射速流派实际上打不满伤害。48 个对象只在开局创建一次。
这也是"平台挡子弹"带来的正面副作用：子弹寿命变短，池压力比之前小。

### 5. 其它收尾

- **新纪录提示**：`GameSettings.SubmitRun` 会把"是否刷记录"记到 `LastRunSetRecord`，结算页显示「★ 新纪录」。
- **Boss 血条四分刻度**：一眼能读出还剩几段，不用去认数字。
- **WebGL 音频解锁**：`GameAudio.KickMusic()` 在每次 `BeginRun`（一定有用户点击/按键）时确认音乐在播——浏览器不允许无交互自动播放。
- 敌人与 Boss 的移动范围统一改读 `RunManager.RoomRight`，不再写死 ±9 / ±7.2。

已知局限：子弹仍然是一次性射线（每帧 `OverlapCircle`），速度 22 时每帧移动约 0.37 单位，
比半径 0.18 大，**极高速下理论上会穿过很薄的碰撞体**；目前平台厚度 0.36 以上，实测未出现。
若以后加穿透型词条或更快子弹，需要改成 `CircleCast` 做连续检测。

## W19：角色缩到 0.62 倍，把操作空间让出来

### 问题

玩家是 1×1 的方块，相机正交半高 6（可视高度 12 格），也就是**人物占了画面高度约 1/12**。
在同一块房间里，这个体积感会让玩家觉得自己"到处都在撞到东西"：贴平台太近、绕怪太挤、
左右两侧的墙也显得压过来。敌人 0.75~1.4、Boss 2.4，比例上还会进一步放大这种压迫感。

### 做法：一个系数管全部

```csharp
private const float CharacterScale = 0.62f;   // 玩家与所有小怪共用
```

- **玩家**：`Start()` 里 `player.transform.localScale = Vector3.one * CharacterScale`。
  碰撞体和精灵都挂在同一个 transform 上，一起缩；落地检测点是 Player 的子物体，
  `localPosition = -0.5` 会跟着缩到世界 -0.31，正好落在脚底，**不需要另外改参数**。
- **小怪**：`Vector3.one * (scale * CharacterScale)`，保持普通 / 快速 / 精英之间的体型差。
- **Boss**：2.4 → 1.9（单独常量 `BossScale`），仍然明显大于其他单位，但不至于占掉半个屏幕。

### 必须跟着改的数值（不改会出现"看着小、判定还大"）

| 位置 | 原来 | 现在 | 原因 |
| --- | --- | --- | --- |
| 冲锋怪接触判定 | 1.1 / 0.85 | 0.72 / 0.62 | 双方体型都缩了，判定要跟着收，否则隔着半个身位就掉血 |
| Boss 接触判定 | 1.3 / 1.6 | 1.05 / 1.3 | 同上 |
| 我方子弹半径 / 视觉 | 0.18 / 0.25 | 0.14 / 0.19 | 与缩小的敌人匹配 |
| 敌方子弹半径 / 视觉 | 0.20 / 0.30 | 0.16 / 0.22 | 同上 |
| 枪口偏移 | 0.7 | 0.45 | 0.7 对 0.62 的角色来说已经在身体外面了 |
| 命中粒子尺寸 | 0.16 | 0.12 | 不缩的话每次命中像炸开一块砖 |
| 出生高度 | 地板 +1.2 / 平台 +0.8 | +0.6 / +0.5 | 半个身位就够，避免开局先自由落体一段 |

### 顺带把空间用起来

角色变小、同屏能容纳的东西变多，所以：

- **悬浮平台 4~6 → 5~7 块**：走位路线更多，也更容易找到能挡子弹的掩体；
- **敌人站位范围**从写死的 `-7~7` 改成 `boundLeft+1.2 ~ boundRight-1.2`，
  铺满整个房间（房间边界现在是 ±10 左右，之前有一大截是空的）。

### 没有动的东西（有意为之）

跳跃物理完全没改：`jumpHeight 3.2 / timeToApex 0.46 / 下落 1.35`，总滞空仍是 0.86 秒。
角色变小后跳跃高度相当于 5.2 个身位，看起来"跳得高"，但滞空时间没变——
这正是留给玩家的操作窗口：空中能调整落点、能绕过冲锋怪、能从平台上方跨过去。
如果跟着缩放去改跳跃，平台高度、词条强度、Boss 冲撞的躲避节奏全都要重新配一遍，
收益远小于风险。

已知局限：角色小、子弹也小，4K 显示器上如果窗口很小，弹幕会不太好辨认；
如果之后收到这类反馈，优先加大子弹而不是把角色改回去。

## W20：无尽模式 + 平台布局重做

### 1. 平台"看起来很挤"的真正原因

不是数量太多，而是**没有分配水平空间**。原来的逻辑是纯随机撒点：

```csharp
for (int attempt = 0; attempt < 10; attempt++) {
    x = 随机; y = 随机(两档之一 + 0~0.5 抖动);
    if (!OverlapsFloat(x, w, y)) break;      // 放不下就把重叠的那块硬摆上去
}
```

5~7 块平台挤在 20 个单位宽的房间里，重试 10 次大概率还是冲突，最后 `break` 出去照样摆放 ——
于是出现两块贴在一起、或者一高一低正好叠成"台阶"的情况，视觉上就是一团。

现在改成**等宽槽位 + 高低交替**：

```csharp
float slot = span / count;                                  // 每块平台自己的水平区间
float w = clamp(slot * (0.55~0.73), 1.5, 2.8);              // 宽度只占槽位的一部分
float x = slot 中心 + 抖动(≤ (slot - w) * 0.4);              // 抖动范围由槽位宽度决定
bool high = (i % 2) == 1;                                    // 相邻两块永远不会同高
float y = FloorTop + (high ? 2.75 : 1.55) ± 0.1;
```

三条保证，都是**结构上**成立的，不依赖重试：

1. 相邻平台之间一定留有 `slot - w` 的缝（10 单位房间里约 1.2~1.8），能站人也能过子弹；
2. 相邻平台永远一高一低，跳起来有节奏，也不会连成一道挡路的墙；
3. 高低差固定 1.2，远小于跳跃高度 3.2，从低台上高台不需要精确落点。

块数从 5~7 降到 **4~5**。之前的"多放几块"是为了掩盖重叠，现在布局有节奏了，少反而更清楚。
`OverlapsFloat()` 那个"重试 10 次"的补丁式方法已删除。

### 2. 无尽模式

标题页两种玩法：

| 模式 | 结构 | 终点 |
| --- | --- | --- |
| 标准 | 3 波，第 3 波是 Boss | 打赢 Boss = 通关 |
| **无尽** | 一波接一波，**每 5 波一个 Boss** | 没有终点，看能撑到第几波 |

实现上没有复制一套流程，而是把"第几波"抽成一个函数：

```csharp
private bool IsBossWave => mode == Mode.Standard
    ? roomIndex >= roomCount - 1
    : (roomIndex + 1) % BossEvery == 0;      // BossEvery = 5
```

波次参数也走同一个入口 `WaveSpecFor(index, out ...)`：标准模式查表（保持原来的手感曲线），
无尽模式用公式，避免为无尽再写一张 20 行的表：

| 项 | 无尽模式公式 | 封顶理由 |
| --- | --- | --- |
| 敌人数 | `2 + index/2` | 封顶 8 只：再多屏幕上全是子弹，没有走位空间 |
| 敌人血量 | `2 + index/2` | 封顶 14：不封顶会变成"打不动的墙" |
| 开火节奏 | `interval × max(0.65, 1 - index×0.02)` | 最快 65%，再快就是纯弹幕 |
| 类型权重 | 炮台/冲锋/快速随波数上涨，普通怪被挤掉 | 后期以"逼走位"的怪为主 |

**Boss 血量按第几个 Boss 递增**（`30 + bossIndex × 12`），否则第 10 波的 Boss 和第 5 波一样好打。

几个必须处理的边界：

- **打完 Boss 继续**：标准模式直接 `Finish(true)`；无尽模式回 1 血 + 三选一，然后进下一波。
- **词条池被叠满**：无尽跑得够远一定会遇到"所有词条都到 maxStacks"。这时 `OfferChoices` 会拿到空列表，
  以前会弹一张空面板把玩家锁住（只能等 12 秒自动兜底）。现在直接跳过选卡、回 1 血进下一波。
- **记录**：`GameSettings` 新增 `BestWave`，标题页与结算页都会显示"最远第 N 波"。
  无尽模式里**第一次超过历史最远波数**时会弹一次「★ 超过最远记录」并播通关音效，
  只在刚超过时提示一次——每波都提示就变成噪音了。
- **结算页**：无尽模式显示「撑到了第 N 波」；标准模式仍是「通关 / 阵亡」。

### 3. 顺手补的

- 暂停面板多了一行「标准模式 · 第 2 / 3 波」/「无尽模式 · 第 7 波」，暂停时不用回忆自己在哪。
- 结算页多了「返回标题（换模式）」，不用先回标题再重进。
- 标题页快捷键：`空格 / 回车` 开标准，`E` 开无尽。

已知局限：无尽模式没有独立排行榜，只有本地 `BestWave`；波次难度在 20 波左右趋于平台期
（数量与血量都封顶），之后再难只能靠节奏百分比继续收紧。

## W21：给它一个世界观，让玩家一眼认出自己

### 1. 剧情：一句话设定 + 五个文本点

一个只有三种波次的房间，硬塞长篇叙事反而会打断节奏。所以剧情只做**五个接触点**，
全部集中在 `Story.cs`（改剧情只改一个文件）：

> 世界被「潮」淹了。你是最后一个守灯人，灯是唯一的光，「蚀」从黑暗里涌进来。

| 接触点 | 文本 | 作用 |
| --- | --- | --- |
| 标题 | 守灯人 / THE LAMPLIGHTER | 定调，替掉原来那行"2D 平台射击 · 轻量肉鸽"（这是描述不是标题） |
| 序章（开局前覆盖层） | 「灯油只剩一夜。／你是最后一个守灯人，城里的人早就走了。／撑过三次涨潮——或者，一直撑下去。」 | 三句话交代处境、目标和两种模式的差别 |
| 波次横幅 | 第一次涨潮 → 第二次 → 第三次；Boss 是「潮眼苏醒」 | 把"WAVE 2/3"这种工程词换成叙事词 |
| 选卡面板 | 「往灯里添一点什么」 | 词条在这个世界观里是给灯添的东西 |
| 结算 | 通关「灯，又亮了一夜。」／失败「灯灭了。」／无尽「灯灭了 · 你撑到了第 N 次涨潮」 | 让失败也有余味，同时把波数说清楚 |

**没有给剧情单开一个 `Phase`**。加 `Phase.Brief` 意味着 `IsPlaying` / `IsControllable` /
所有系统里的 `if (!IsPlaying) return` 都要重新过一遍，风险远大于收益。改用标题页上的一个
`briefOpen` 覆盖层：点模式 → 显示序章 → 任意键（或点「点灯 · 开始」）才真正 `BeginRun`。
`ReturnToTitle()` 里会把 `briefOpen` 复位，避免从暂停菜单回标题时卡在序章。

### 2. 玩家辨识度：给方块一张脸

之前玩家和敌人都是纯色方块，只有颜色不同 —— 敌人有 5 种颜色（红/橙/绿/蓝/紫），
玩家那个颜色在混战里根本认不出来。现在三层区分，都不需要新资源：

1. **暖白本体 + 深色描边**：`PlayerVisual` 用同一张方块精灵放大 1.34 倍垫在下面当描边
   （`sortingOrder` 比本体小 1）。敌人全是饱和色，暖白在任何一个敌人旁边都跳出来。
2. **两只眼睛**：两个 0.15 倍的小方块，跟着**准星**左右偏移 —— 不看准星也知道自己在朝哪打。
   敌人没有脸，这一条是"这是角色、那是怪"的核心区分。
3. **排序**：本体 `sortingOrder` 提到 12（敌人在 5），描边 11、眼睛 13，保证永远压在敌人上面。

配套改了 `PlayerHealth`，因为它的受伤闪烁原来是直接 `sr.enabled = !sr.enabled`：

- 闪烁要连描边和眼睛一起开关（`PlayerVisual.SetVisible`），否则会出现"本体在闪、轮廓一直亮着"；
- 新增 `SetBaseColor()`：`PlayerVisual` 会把本体改成暖白，而 `PlayerHealth` 在 `Awake` 里
  缓存了场景里的旧颜色，不更新的话下次复活会被盖回去。

已知局限：眼睛是两块方块，没有朝向动画；角色也没有跑动/跳跃的姿态变化（还是纯色块 + 描边）。
要做真正的角色动画，需要引入骨骼或序列帧资源，那就不再是"零资源"的约束了。

## W22：从方块换成角色美术（v1.1）

### 为什么这一步值得做

前面所有打磨（描边、眼睛、颜色区分）都是在"方块"这个载体上做文章。到 v1.1 换成真正的插画角色，
辨识度直接从"靠颜色区分"变成"靠轮廓区分"——这是量级不同的提升，也是"能上架"和"技术 demo"的分界线。

### 五个角色，一套统一画风

| 角色 | 形象 | 设定对应 |
| --- | --- | --- |
| 玩家 | 兜帽 + 披风 + 提灯的守夜人 | 「守灯人」，提灯是唯一的光 |
| 普通 / 快速 / 精英射手 | 破翼飞蛾状「蚀」，红眼 | 从黑暗里涌来的东西 |
| 冲锋怪 | 低伏的双角甲虫 | 贴地撞人，逼你跳 |
| 炮台 | 单眼 + 三管炮台 | 不动，三连散射 |
| Boss | 巨大的单眼 + 触手「潮眼」 | 剧情里的最终潮眼 |

生成时用同一组风格词（cel-shaded、black outline、centered、transparent）保证画风一致。

### 一个必须处理的坑：生成图不是真透明

`ImageGen` 即使指定 `background: transparent`，产出的 PNG 仍是 **colortype 2（RGB，无 alpha 通道）**——
"棋盘格"只是画上去的图案。直接进 Unity 会得到 5 个灰色方块背景，比原来的纯色方块更难看。

处理办法：走 `buddy-image-processing` 的 **matting**，把主体从棋盘格背景里抠出来，
同时右下角的「AI生成 WORKBUDDY」水印也一并被当成背景去掉。抠完验证 5 张全是 **colortype 6（RGBA）**。

### 接入方式：不碰任何数值

`ArtStore.cs` 运行时从 `Resources/Art` 读图，`Sprite.Create` 用 `PPU = 1024 / 1.35`：

- 1024px 图对应 1 个世界单位 → 原有 `CharacterScale=0.62`、`BossScale=1.9` 等缩放数值**一个数都不用改**；
- 图里角色只占画布中间约 70%，除以 1.35 补偿，让可见主体和原来的方块差不多大；
- 加载失败返回 null，各调用点用 `?? enemySprite` 退回纯色方块，缺图不会白屏。

配套改动：

- **玩家**：`PlayerVisual` 换成美术后关掉程序化描边和眼睛；`body.flipX` 按准星左右翻转（不缩放 transform，避免影响碰撞）；
- **敌人**：`Enemy.Init` 原来会把 `sr.color` 设成饱和纯色，有图后改传淡染色（快速偏暖、精英偏紫），否则整张插画会被染成一坨色块；
- **Boss**：蓄力闪黄、半血狂暴同样改成淡染色；`hasArt` 由 `sr.sprite == ArtStore.Boss` 判断。

已知局限：只有静态单帧，没有行走/攻击动画；角色朝向只有左右翻转，没有背面/侧面切换；
图片总计约 4.6 MB，WebGL 包会从 3 MB 涨到约 7~8 MB。

## W23：让静态精灵"活"起来（v1.2）

### 问题

v1.1 换成插画后，角色从"方块"变成了"贴纸"——画得再好，站着不动就像一张图贴在那里。
真正的游戏里角色有重量、有惯性。

### 核心原则：视觉和物理彻底分层

这是本轮最重要的架构决定。**所有形变只作用在独立的 `Visual` 子节点上，根节点只保留碰撞体和物理**：

```
Player (根节点: BoxCollider2D / Rigidbody2D / localScale=0.62)
└── Visual (只做缩放 / 旋转 / 翻转)
    ├── Body (精灵)
    ├── Outline      ← 无图时才启用
    └── EyeL / EyeR  ← 无图时才启用
```

如果直接改根节点 transform，会连带把碰撞体一起变形，出现"看着跳过了、判定却没过"——
这类 bug 极难查，因为画面和物理都"看起来没问题"。分层之后两边互不干扰，**碰撞数值一个都没动**。

### 玩家的三种动效（Combat+Platformer 通用语言）

| 动效 | 触发 | 参数 |
| --- | --- | --- |
| **起跳拉伸** | 离地瞬间且上升 | y 放大最多 30%，x 收 16% |
| **落地压扁** | 着地瞬间且下落速度 > 2 | 压扁量按下落速度算，0.45 秒内回弹；同时脚下喷 5 粒尘 |
| **待机呼吸** | 站地且水平速度 < 0.2 | y ±2.5%，2.6 rad/s |
| **奔跑倾斜** | 按水平速度 | 最多前倾 8° |

`PlayerMotor` 新增三个只读属性 `Grounded / VerticalSpeed / HorizontalSpeed` 给视觉层读，
没有引入新的输入或事件系统。

### 敌人的三种动效

- `Shooter / Turret`：悬停呼吸 ±4%，每只按 x/y 位置错开相位（避免整齐划一如复制粘贴）；
- **开火前膨胀**：`TelegraphProgress` 让"要开枪了"除了颜色预警还有形变，余光也能察觉；
- `Charger`：冲刺时前倾最多 10° 并收敛呼吸，看起来是"压低身体往前撞"。

### 一个容易踩的坑：精灵引用的缓存

`Enemy` 原来在 `Awake` 里把 `sr` 缓存成字段。视觉层把精灵移到子节点后，
这个缓存会指向被关掉的根节点精灵——闪白、染色全部失效，而且**不报错，只是看不见**。

改法：把 `sr` 从字段改成属性，内部动态取 `EnemyVisual.LiveSprite`，取不到才回退根节点：

```csharp
private SpriteRenderer sr
{
    get {
        EnemyVisual vis = GetComponent<EnemyVisual>();
        if (vis != null && vis.LiveSprite != null) return vis.LiveSprite;
        return cachedSr;
    }
}
```

同理 `PlayerHealth` 的显隐也改为转发给 `PlayerVisual`，否则受伤闪烁会把根节点的旧精灵重新打开，造成重影。

已知局限：仍是单帧精灵的形变，不是真正的序列帧动画；没有骨骼，转身只有左右翻转。

## W24：更自然的动作与打击动效（v1.3）

### 从"会变形"到"有反馈"

v1.2 解决了"贴纸感"，但还缺一层：**玩家的操作要在画面上有回响**。这一轮加的是事件驱动的动效。

新增 `FxRings.cs`，一个组件提供三种程序化效果（柔边圆精灵运行时生成，零贴图资源）：

| 效果 | 触发 | 视觉 |
| --- | --- | --- |
| **落地冲击环** | 落地瞬间，强度按落地速度 | 贴地椭圆快速扩散 + 淡出（ease-out 2.5 次方），配合原有扬尘 |
| **起跳扬尘环** | 离地瞬间 | 更小更淡的一圈 |
| **枪口闪光** | 每次开火 | 亮色柔光沿射击方向拉长 1.7 倍，0.09 秒 |
| **冲刺残影** | 冲锋怪速度 > 5 | 每 0.07 秒留一个淡出副本，读起来是一条轨迹 |

为什么单独做组件而不是塞进 `HitParticles`：**视觉语言不同**。
`HitParticles` 是"方块四散"表达"打中了"；冲击环是"圈向外扩"表达"有力作用在地面上"。
混在一起画面语义会乱。

### 玩家的两种新反馈

- **开火后坐**：`PlayerVisual.FireKick()` 让视觉层沿射击反方向顿一下（最多 0.06 世界单位），
  枪口位置用与子弹**完全相同的 muzzleOffset**，视觉和判定对齐；
- **受击后仰**：`PlayerVisual.Hurt()` 后仰 + 红色爆散，和开火后坐共用一套偏移字段。

这里有个真实的冲突：高射速时会一直开火，受击的后仰会被下一发的后坐立刻覆盖，
玩家"挨打"的感觉就没了。加了一个 `hurtLock = 0.22f`：受击后短时间内 `FireKick` 直接 return，
保证受击反馈完整播完。这是那种"不实际跑起来根本想不到"的问题。

### 特效也会拖垮帧率，所以要限流

极端 build（射速 30 × 5 弹丸 + 3 只冲锋怪）下，闪光和残影对象会持续堆积。
`FxRings` 加了 `MaxLive = 40` 上限，超了就跳过新特效。

计数在 `OnDestroy` 里统一递减（用 `counted` 标志防重复扣），这样正常结束和场景切换
都不会泄漏配额——如果只在 `Update` 里递减，切场景时会永久少一截额度。

### 沿用不变的铁律

所有新动效仍然只作用于 `Visual` 子节点：冲击环和闪光是独立 GameObject，
后坐改的是 `visualRoot.localPosition`，残影只用精灵快照。
**根节点碰撞体、CharacterScale、跳跃数值一个都没动。**

已知局限：残影是整张精灵的淡出，不是真正的运动模糊；闪光是柔光圆，没有枪械造型。

## W25：Boss 的重量感与场景的呼吸（v1.4）

### Boss 不能再是"只会变色的方块"

玩家和小怪都有了形变，Boss 反而最僵硬——只有变色和套一个固定的 pulse 正弦。
这一轮把它补成全场最有压迫感的单位：

| 状态 | 新动效 |
| --- | --- |
| 待机 | 缓慢呼吸（2.1 rad/s，±3.5%），是全场最"沉"的节奏 |
| 蓄力 | 每 0.12 秒在脚下放一圈收紧的光环 —— 颜色闪烁之外的第二条倒计时线索，余光也能读到 |
| 冲撞 | 撑开到 1.08 倍 + 每 0.1 秒留一个残影（和冲锋怪同一套视觉语言，但 Boss 更大更慢） |
| 硬直 | 收缩到 0.96 倍，明确"现在虚弱，可以反打" |
| 受击 | `Flinch()` 短暂高频抖动（0.18 秒衰减） |
| 半血 / 死亡 | 空中爆发环（正圆，不是贴地椭圆） |

关键实现：所有 scale 赋值统一走 `ApplyVisualScale(base)`，内部叠加呼吸和抖动后再写根节点。

**为什么 Boss 可以直接改根节点 scale，而玩家/敌人必须分层？**
Boss 的碰撞是**手算半径**（`contactRadiusX/Y`），不读 `transform.localScale`；
它的 `BoxCollider2D` 只作为子弹命中的开关（enabled true/false），不承担精确判定。
玩家和敌人则依赖 collider 的实际尺寸，所以必须把形变放到 `Visual` 子节点。
——同一个项目里两种做法并存，原因是它们的碰撞模型不同，而不是随手写的。

### 场景也需要"活着"

「守灯人」的核心意象是：世界被潮水淹没，灯是唯一的光。但如果背景是一片静止渐变，
这个意象立不住——没有参照物，玩家感觉不到"暗"。

新增 `Ambience.cs`：18 个确定性分布的微光点缓慢上浮 + 横向摆动，
1/3 暖色（像被灯照到的尘）、2/3 冷色（潮气泡泡），sortingOrder = -50 夹在背景和游戏对象之间。

- **对象池**：18 个固定对象，飘出顶部就从底部回来，不 Instantiate/Destroy；
- **确定性**：位置用 `Fract(k * 常数)` 推导，不引入新随机源，不破坏 seed 复现；
- 暂停 / 敌人进场期间冻结，和其他系统保持一致。

已知局限：尘埃不响应玩家位置（不会"被灯照亮"），只是固定颜色；要做真正的光照交互需要 shader。

## 一不小心踩的坑：别把 Editor.log 当成编译日志

连续加了好几轮代码后我想验证"到底编译过没有"，查 `Editor.log` 看到最后 200 行无 `error CS`，
就一直报"编译通过"。**这是错的。**

团结引擎的这个实例把 `Editor.log` 当成**启动日志**用：文件里只有授权握手和命令行参数，
最后一行是启动完成，之后再也不写。真正的编译产物在别处：

| 真相来源 | 路径 | 能证明什么 |
| --- | --- | --- |
| 脚本程序集 | `Library/ScriptAssemblies/Assembly-CSharp.dll` | 类是否真的编进去了（查类名字符串） |
| Bee 构建日志 | `Library/Bee/tundra.log.json` | 编译节点退出码（`exitcode: 0` 且无 `type:error`） |
| 资源导入 | `Assets/Scripts/X.cs.meta` 是否存在 | 新文件是否被 Unity 导入过 |

用这三样一查就露馅了：`FxRings`/`EnemyVisual`/`ArtStore` 在 dll 里，
但新写的 `Ambience.cs` **既没有 .meta 也不在 dll 里**——它从来没被编译过。之前的"无错误"全是假象。

### 为什么命令行验证也不管用

只要编辑器开着，它就占着 38000 / 38443 端口。第二个实例（即使在完全独立的项目副本里）
会在启动阶段绑定端口失败，6 秒静默退出，连 `-logFile` 指定的日志都写不出来。
所以"另起一个实例批量编译"这条路在编辑器开着时走不通，别浪费时间试。

### 那怎么降低风险

1. **写新脚本时优先用项目里已有先例的 API**。用 grep 数一下：某个 API 在其他 12 个脚本里都用过，
   基本可以放心；如果出现次数是 0，就要警惕版本兼容问题。
   `Ambience` 里我原本用了 `FindObjectOfType<T>()` 和 `Mathf.Floor()`，项目里 0 先例——
   虽然两者在 Unity 2022 分支大概率存在，但没必要赌，改成静态单例引用 + `(int)` 截断，零风险。
2. **静态检查兜底**：所有 .cs 的花括号计数必须平衡（注意用 UTF-8 读取，
   否则中文注释的字节会被 GBK 误判成花括号，得到错误的 5/6 这种结果）。
3. **最终以编辑器里 Console 0 error 为准**。自动检查只能排除低级错误，不能替代实际编译。

这次的教训写下来，是为了以后不再对着一份不刷新的日志说"编译通过"。

### 一个真实教训：替换代码块时删掉了还在用的字段

v1.4 给 Boss 加视觉参数时，我用「替换整块字段声明」的方式编辑：

```csharp
// 原来的三行被我整个换掉了
private Vector3 enterFrom;
private Vector3 enterTo;
private float enterDuration;
```

替换成了新的视觉字段（`flinch` / `chargeTrailTimer` 等）。结果 `Init()` 和 `UpdateEnter()`
还在用那三个字段，编辑器直接报：

```
Assets\Scripts\Boss.cs(74,9): error CS0103: The name 'enterTo' does not exist in the current context
```

**根因**：编辑时把"新增字段"和"删除旧字段"混在一次整块替换里，没检查旧字段是否还有引用。

**正确做法**：新增字段就用一次独立的小 Edit 追加，不要替换已有声明块。
如果确实要删，先 grep 确认引用数为 0。

这个 bug 也再次证明：静态检查（括号平衡、字段扫描）只能兜底一部分，
**真正发现它的是编辑器 Console 的 CS0103**。所以任何"我这边检查过了"都不能替代
在编辑器里按 `Ctrl+R` 后看一眼 Console。

## W26：让动作真正连贯（v1.5）

### 问题：之前的动作是"离散事件 + 匀速回弹"

W23/W24 的 squash/stretch 用 `Mathf.MoveTowards(squash, 0, dt*4.5)` 回弹——
这是**匀速**的，到点就停，动作之间有明显的"断口"：落地压扁后直挺挺恢复，
转身是一个瞬间的 flipX，跑步只有一个固定倾角。看起来像一串独立动作，不是连续表演。

### 改法：弹簧物理 + 连续状态驱动

新增 `Spring.cs`（值类型，零 GC）：

```csharp
public struct Spring {
    public float value, velocity;
    public void Kick(float impulse) { velocity += impulse; }
    public void Step(float target, float stiffness, float damping, float dt) {
        if (dt > 0.04f) dt = 0.04f;              // 卡顿时防止数值爆炸
        float accel = (target - value) * stiffness - velocity * damping;
        velocity += accel * dt; value += velocity * dt;
    }
}
```

阻尼略小于临界值（`damping < 2*sqrt(stiffness)`），动作会**轻微超调再收回**——
这是"有质量"的关键，匀速回弹永远做不到。

四根弹簧分别驱动：压扁 / 拉伸 / 后坐 / 倾斜。事件不再直接设值，而是给冲量：

| 事件 | 原来 | 现在 |
| --- | --- | --- |
| 落地 | `squash = 0.8` | `squashSpring.Kick(-(strength*10+4))` |
| 起跳 | `stretch = 0.7` | `stretchSpring.Kick(vy/14*7+3)` |
| 开火 | `recoil = 1` | `recoilSpring.Kick(-9)` |
| 受击 | `recoil = 1` | `recoilSpring.Kick(-16)`（比开火大） |
| 转身 | 瞬间 flipX | `leanSpring.Kick(-faceSign*6)`，有急停过渡 |

### 连续状态取代一次性触发

- **跑步周期**：`runPhase += dt * (4 + speed01*9)`，身体按相位上下起伏 + 左右摇摆，
  速度越快频率越高——这是"跑起来了"和"在滑行"的区别；
- **空中姿态**：`airStretch = clamp(vy/16, -0.5, 0.5)` 每帧连续映射，
  上升时头上脚下、下落时反过来。不再是起跳瞬间变一下然后冻住；
- **待机呼吸**：只在 `speed01 < 0.05` 时启用，和跑步起伏互斥，不会叠加成奇怪的抖动。

形变合成时 `airStretch` / `bob` / 弹簧值全部相加，所以动作之间是**叠加过渡**而不是切换。

### 版本

`Spring.cs` 是新文件——又踩了一次"新文件需要 meta 才会被编译"的坑。
我这次主动生成了 `.cs.meta`（用一个唯一的 base64 GUID，格式照抄 `Ambience.cs.meta`），
但编辑器当前不响应外部文件变化，**必须按 Ctrl+R** 才会真正编译进去。
编译后请用 dll 字符串验证，不要只看 Editor.log：

```
Library/ScriptAssemblies/Assembly-CSharp.dll 里应有 Spring / squashSpring / runPhase
```


### 后记：Spring 也从"独立文件"改成内联了

和 Ambience 一模一样的坑又发生了一次：我建了独立的 `Spring.cs`，手动生成了 `.cs.meta`，
但 Unity 没认，编辑器直接报 4 个 `CS0246: The type or namespace name 'Spring' could not be found`。

**结论：只要编辑器不响应外部文件变化，任何新 .cs 文件都有风险，不管有没有 meta。**
最终解法是把 `Spring` 结构体内联进 `PlayerVisual.cs`（用它的现有文件，一定能被编译），
然后删掉 `Spring.cs` 和它的 meta。代价只是这个文件稍微长一点，换来的是零导入风险。

以后加新工具类，优先内联到已有的 .cs 文件里；确实要建新文件时，必须在编辑器里
按 Ctrl+R 确认它被导入（dll 里能查到类名）之后再继续。

## W27：完整关卡流程 —— 4 章 20 波通关（v2.0）

### 需求与定案

把"打完就结束"的 demo 做成有始有终的完整游戏：
**每 5 波一个 Boss，打完第 4 个 Boss 通关，每个大关（章）怪物更难。**
保留无尽模式作为独立选项（标题页空格=标准通关，E=无尽）。

### 章节结构

```
标准模式 = 4 章 × 5 波 = 20 波
  第 1~4 波  第一夜   普通怪练手（逐波引入快速）
  第 5 波    BOSS #1  潮眼苏醒（血 30）
  第 6~9 波  第二夜   引入冲锋怪
  第 10 波   BOSS #2  （血 42）
  第 11~14 波 第三夜  引入炮台
  第 15 波   BOSS #3  （血 54）
  第 16~19 波 第四夜  全类型混编
  第 20 波   BOSS #4  （血 66）→ 通关
```

推演出的难度曲线（脚本验证过）：

| 波 | 1 | 3 | 5(B) | 6 | 10(B) | 15(B) | 20(B) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 敌人数 | 2 | 3 | 4 | 3 | 5 | 6 | 7 |
| 血量 | 2 | 3 | 4 | 4 | 6 | 8 | 10 |

注意第 6 波敌人从 4 回落到 3——**每章开头给一个喘息**，然后章内再爬升。

- `BossDefeated` 里判断 `bossIndex >= StandardChapters-1` 才通关，前 3 个 Boss 打完回 2 血 + 三选一继续。
- 章节横幅 `Story.ChapterBanner(chapter)` 在每章第一波显示（第一夜/第二夜/...），
  HUD 显示"第 N 夜 · 第 X/20 波 · M 波后潮眼苏醒"，进度一目了然。
- 标准模式也引入开火节奏收紧（每章 -6%，封底 65%），之前只有无尽有。

### 又踩一次：改错副本，改动被覆盖
