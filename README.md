# 守灯人 · The Lamplighter

> 一个 3–10 分钟一局的小游戏：跑跳射击、清场三选一词条、掩体挡子弹、seed 可复现。
> **一句话设定**：世界被「潮」淹了，你是最后一个守灯人。灯是唯一的光，「蚀」从黑暗里涌进来。
> 目标是做到能发布（v1.0），而不是停在"能跑的技术 demo"；进度见 `Docs/GAME-COMPLETION-ROADMAP.md`。

## 叙事设计

剧情只做**五个接触点**，全部集中在 `Story.cs`：标题（守灯人）、序章三句话、波次横幅（"第一次涨潮"而不是 "WAVE 1/3"）、选卡面板（"往灯里添一点什么"）、结算（"灯，又亮了一夜。" / "灯灭了。"）。

为什么不再多做：一局只有三次涨潮，长篇对话会直接打断节奏；而且没有美术资源，CG、立绘、对话框都做不出来。**把叙事压进玩家一定会看到的五个点**，比塞一段能跳过的开场白有效得多。

也没有为剧情单开一个 `Phase`——加 `Phase.Brief` 意味着 `IsPlaying` / `IsControllable` 和所有系统的短路条件都要重过一遍。改用标题页上的一个覆盖层：点模式 → 序章 → 任意键才真正开局。

## 玩法与操作

| 操作 | 键位 |
| --- | --- |
| 移动 | A / D 或 ← / → |
| 跳跃 | Space（轻点跳得矮，长按跳得高） |
| 瞄准 | 鼠标（角色眼睛会跟着准星转） |
| 开火 | J 或鼠标左键（按住连发） |
| 暂停 / 设置 | Esc（画面震动档位、音量、重开、返回标题） |
| 快速重开 | 结算页 R（同 seed，零点击再开） |
| 直接开局 | 标题页 空格 / 回车 |
| 选词条 | 点卡片，或按 1 / 2 / 3 |
| 导出跳跃曲线 CSV | K |

一局 3 波敌人，全部在一间**封闭大房间**里发生：整块地板压到画面底部、无坑，两侧是**看得见的墙**——位置按相机正交半宽算出来，永远贴住画面左右边缘、只露出 0.45 个单位，所以"看得见的那条竖条"和"走不过去的地方"完全重合，不会出现空气墙。**每个小关卡都会重新生成 4~5 块悬浮平台，并在随机位置出生**（70% 地板、30% 平台顶），同 seed 可完整复现。敌人从墙后飞入站位，飞行 1.1~1.7 秒、逐个错开；**进场期间玩家操作与双方子弹被冻结**（只停玩法系统，不动 `Time.timeScale`），最后一只落地后恢复。

类型按波次递进：第 1 波只有普通怪练手，第 2 波加入快速怪与冲锋怪，**第 3 波是 Boss 战**。每波清场后三选一词条并回复 1 点血量（选卡时仍可自由走动，界面与操作互不阻塞），打完 Boss 进入结算页，可同 seed 重玩或开新的一局。

**两种玩法**：**标准模式**有明确终点（3 波 + Boss，赢了就是通关）；**无尽模式**一波接一波、**每 5 波一个 Boss**，看你能撑到第几波。两者共用同一套波次入口——`IsBossWave` 决定这一波刷小怪还是刷 Boss，`WaveSpecFor(index)` 决定数量 / 血量 / 类型权重：标准模式查固定表（保住原手感曲线），无尽模式用公式递增（数量与血量都封顶，难度主要来自开火节奏收紧，避免后期变成"打不动的墙"）。Boss 血量按"第几个 Boss"递增，第 10 波不会和第 5 波一样好打。历史最远波数存本地，无尽模式里第一次超过时会弹一次「★ 超过最远记录」。

**平台布局**：不是纯随机撒点，而是**等宽槽位 + 高低交替**——每块平台只在自己那段水平区间里抖动，宽度只占槽位的 55%~73%，所以相邻两块之间一定留得下一条缝；高度在 1.55 / 2.75 两档交替（差 1.2，远小于跳跃高度 3.2）。这三条都是结构上成立的，不依赖"随机重试到不重叠"，所以不会出现两块贴在一起或叠成台阶。

**Boss**：单个大型敌人，循环「漂移 → 0.5 秒变色蓄力 → 出招 → 硬直」，出招在**扇形七连弹幕**和**横向冲撞**之间交替；蓄力阶段会闪黄放大给预警，硬直阶段是反打窗口，顶部有独立血条。打完 Boss 即通关。

## 我实现的核心机制

**手感**：先定"跳 3.2 单位、0.46 秒到顶"，反推 `v0 = 2h/t ≈ 13.9 u/s`、`g_up = v0/t ≈ 30.2 u/s²`；下落重力设为上升的 1.35 倍（≈40.8），落地依然干脆但不"砸"。配合土狼时间 0.12s、跳跃缓冲 0.12s、松键截断 0.5、空中控制系数 0.5，总滞空约 0.86 秒。所有参数集中在 `PlayerStats`（ScriptableObject），运行时可用调参面板实时改。

**角色体积**：玩家原本是 1×1 的方块，占画面高度约 1/12，在场上有压迫感、走位也挤。现在统一缩到 **0.62 倍**（敌人共用同一系数，Boss 单独 1.9），相对体积降到约 1/19——同一块场地里可用于走位、绕后、找掩体的空间明显变多。碰撞判定按同一比例收紧（冲锋怪接触 1.1→0.72、子弹半径 0.18→0.14、枪口偏移 0.7→0.45），避免"看着小、判定还大"。**跳跃物理一点没改**：角色小了之后相当于能跳 5.2 个身位，滞空仍是 0.86 秒，这段空中时间就是留给玩家调整落点和绕过的操作窗口。

> 第一版是 3.0 单位 / 0.35 秒到顶 / 下落 1.6 倍（总滞空 0.63 秒），实测反馈是"太重、像块砖"，于是把到顶时间拉长 31%、下落倍率降到 1.35，并把 `maxFallSpeed` 从 25 降到 18。

**战斗反馈（分级，而不是全开）**：子弹对象池（16 发预分配，运行时零分配）、击退、闪白、命中粒子、合成音效。反馈按事件频率分配预算——**普通命中只轻抖 0.020 单位**；击杀与受伤才触发更大震动。0.05 秒内的连续命中合并取最大值、绝不线性叠加，抖动幅度按剩余时间二次衰减。震屏整体可被玩家的「关 / 弱 / 标准 / 强」设置缩放。

> 这里踩过两个真实坑。第一版每发子弹命中都触发 0.12 单位随机跳变 + 全局 `timeScale = 0`，6 发/秒时等于每秒十几次地震叠加十几次卡顿——教训是**反馈要有层级和预算，同时全开等于全关**。第二版改成 `timeScale = 0.05` 做顿帧，结果它一旦没被还原成功，全局时间就永久卡在 5% 速度，画面几乎静止、和暂停无法区分——教训是**不要用全局时间缩放表达局部手感**，现在改成纯震屏，`timeScale` 恒为 1 并带运行时自检。

**肉鸽闭环**：**20 条词条**（11 条纯强化 + 9 条带代价的取舍）只描述"改哪个字段 / 怎么改 / 最多叠几层"，战斗代码一行不改；所有数值收敛到扁平的 `RunStats`（射速 / 弹丸数 / 伤害 / 移速倍率 / 生命上限 / 敌人血量），战斗侧永远只读它。`maxStacks` 防止叠加爆炸，`ApplyOne` 里逐项夹紧防止数值失控。所有随机走同一个 `System.Random(seed)`，同 seed 可完整复现。

> 取舍卡的作用不是"更难"，而是让 build 分化：`伤害 +1（射速 -15%）` 和 `射速 ×1.35（伤害 -1）` 会走向两种完全不同的手感，玩家在选的时候其实是在选"我要打成什么样"。

**Boss 与两阶段**：第 3 波换成单体 Boss，循环「漂移 → 蓄力（0.5s 变色闪烁 + 8% 体型脉冲）→ 出招 → 硬直」，招式在**扇形弹幕**和**横向冲撞**之间交替（随机连续两次冲撞是无解的，所以不用随机）。血量过半进入二阶段：预警 0.5→0.34 秒、扇形 7→9 发、冲撞速度 ×1.2、硬直缩短，本体变红并在血条上标注「狂暴」——难度提升来自节奏而不是数值。

**表现层（零资源依赖）**：背景是代码生成的竖向渐变；敌人死亡先膨胀 35% 再缩没 + 淡出（而不是直接 `SetActive(false)`）；玩家死亡一次明显的爆散；每波开场有一帧 0.2 透明度的闪白作为起始节拍；**背景音乐也是合成的**——`MusicSynth` 用 `AudioClip.Create` 叠出 4 小节无缝循环（A 小调 i-VI-III-VII：低音 + 八分琶音 + 底鼓 + 反拍 hi-hat），固定种子噪声保证每次音色一致，`tanh` 软限幅防止叠加失真。整包不含任何音频/图片资源。

**难度曲线与失败归因**：波次数量 / 血量 / 类型权重都做成表（`WaveCount / WaveHp / WaveNormal / WaveFast / WaveCharger / WaveTurret`），第 1 波只有普通怪，第 3 波才引入炮台与精英——避免新手第一分钟就被劝退。结算页不只说"阵亡"，而是给出**命中率（命中数/发射数）、受伤点数、最后一击来自哪种怪**，让失败可解释；每次选完词条回 1 血，保证中段不至于彻底无解。

**场地与出场节奏**：一间封闭大房间——整块地板压到画面底部、左右延伸到相机外，两侧是**看得见的墙**（位置由 `orthographicSize × aspect` 算出，只往画面里露 0.45 个单位，拖窗口会自动跟随）。**平台和墙都会挡子弹**，所以悬浮平台不只是落脚点，还是掩体：躲到平台后面，射手怪和炮台就打不到你——这让"站在哪"第一次变成了决策。**每关重新生成 4~6 块悬浮平台**（低/高两条高度带，都在跳跃高度内），并挑一个随机出生点（70% 地板、30% 平台顶）。敌人不是凭空出现，而是从墙后飞入站位：墙的排序层高于敌人，所以是先被挡住再钻出来；每只飞 1.1~1.7 秒、彼此错开 0.12 秒，走**三次 ease-out** 曲线——刚进场几乎是全速冲进来，接近站位时急收，配合轻微上抛弧线。**进场期间冻结玩家操作与双方子弹**：只门控自己的系统，`Time.timeScale` 始终保持 1（用 `timeScale = 0` 会让 Unity 编辑器误判为暂停、Game 视图失焦）。清场后的三选一是底部一排小卡片，不压暗全屏、不挡战斗区，选卡时玩家仍可自由走动。

**可读性**：敌人开火前 0.28 秒逐渐发亮（远程攻击有预警就不需要背板）；受伤瞬间屏幕四边红闪、剩 1 血时边条缓慢脉动；每波开场有一帧轻闪白作为节拍；Boss 血条带四分刻度。这些都不占用战场中心，也不会盖住准星。

## 技术栈与选型理由

| 层 | 选择 | 为什么 |
| --- | --- | --- |
| 引擎 | Unity 2022.3 LTS / 团结引擎 | 岗位匹配度高、2D 生态成熟、WebGL 可发 itch.io |
| 语言 | C# | 与岗位主流一致；用版本宏兼容 `velocity` / `linearVelocity` |
| 参数 | ScriptableObject + struct `RunStats` | 参数脱离场景、运行时可调；值类型避免引用拷贝污染基础值 |
| 物理 | 自算非对称重力 + `FixedUpdate` | 引擎自带重力是恒定的，做不出"上升慢下落快" |
| 随机 | `System.Random(seed)` | 可复现；不混用引擎全局随机源 |
| UI | `OnGUI` | 原型阶段最快，不引入 UGUI 依赖 |
| 版本控制 | Git | 小步语义化 commit，提交历史本身是证据 |

## 构建与运行

1. Unity 2022.3 LTS 或团结引擎，打开项目
2. `Tools → Build W4 Scene` 生成演示场景（也可用 W1/W2/W3 场景）
3. `Edit → Project Settings → Player → Other Settings → Active Input Handling` 设为 Both
4. 按 Play；`Tools → Build WebGL (for itch.io)` 打包到 `Builds/WebGL`

## 架构

```
InputReader → PlayerMotor → Weapon → Bullet → Enemy → RunManager → HUD
                  ↑            ↑                          ↑
             PlayerStats   RunStats(词条)        System.Random(seed)
```
依赖方向单向；`HitFeedback` 作为横切层被各模块调用；子弹与敌人不走 `Rigidbody2D`，规避不同引擎分支的速度 API 差异。

## 已知局限 / 下一步

- 子弹用逐帧 `OverlapCircle` 判定，不是连续检测；速度 22 时每帧位移 0.37、直径 0.36，实测不穿，但再提速就要换 `CircleCast`
- 除去 Boss 的 5 种小怪都没有寻路与避障；冲锋怪靠玩家无敌帧兜底
- Boss 只有两个招式（二阶段只是更快的同一套），没有召唤与三阶段
- 只有一间房间，没有多房间推进、门与路径选择
- 敌人入场是直线插值 + 竖直弧线，没有路径规划
- 词条只做数值修正，没有改机制（穿透 / 弹跳 / 吸血这类）；也没有稀有度分层，抽卡权重均等
- 词条表暂用静态代码表，可迁到 ScriptableObject 资产
- 敌方子弹与粒子仍用 `Destroy`，未池化
- 美术是纯色块 + 程序生成的渐变背景，没有角色动画帧，也没有视差层
- 音乐是单段 4 小节循环，没有随战斗强度变化的层；玩家死亡后不会淡出

下一步按 `GAME-COMPLETION-ROADMAP.md` 推进：内容已冻结在 v0.12，剩打包 → itch.io 页面 → 试玩收 Bug → 打 tag。
