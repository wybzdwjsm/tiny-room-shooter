# 从 Demo 到「完成」：这个游戏的收尾路线

> 目标变更：不再把项目当"简历素材"来堆功能，而是**做成一款能发出去、别人能玩完的小游戏**。
> 评价标准从"面试官能不能看懂"换成"玩家愿不愿意再开一局"。

---

## 一、什么叫做完（先定义，否则永远做不完）

一个 2D 平台射击肉鸽，"完成"要同时满足下面五条。**任何一条不满足，就还是 demo。**

| 维度 | 完成的判定标准 | 现在 |
| --- | --- | --- |
| **闭环** | 从启动到结局没有断点：标题 → 开局 → 战斗 → 变强 → 结算 → 再来一局；中途能暂停、能退出、能重开；掉出地图不会卡死 | 基本达成（W7 补齐暂停与掉落保护） |
| **内容量** | 一局能玩 8–15 分钟不重复；至少 5 种行为不同的敌人 + 1 个 Boss；词条 ≥20 个且存在取舍 | 接近（3 种行为 / 5 种小怪 + Boss + 20 条含取舍词条；单局仍偏短） |
| **难度曲线** | 前三局大概率失败，第十局能稳定通关；失败原因玩家说得清 | 未达成（难度靠波次硬抬） |
| **表现** | 有背景、有受击/死亡反馈、有音乐、界面风格统一，不像"白盒测试" | 未达成（纯色块 + 合成音效） |
| **可发布** | WebGL 包能上传 itch.io，页面有截图/视频/操作说明，别人打开就能玩 | 代码就绪，未发布 |

**v1.0 的定义**：上面五条全绿 + 连续 3 次完整试玩无阻断性 Bug。

## 二、剩下的四个阶段

### P1 · 把"能玩"变成"玩得下去"（约 1 周）

已完成：
- ✅ 暂停菜单、震屏档位与音量设置、掉落保护、最佳记录、命中反馈分级（v0.4）
- ✅ **失败要有解释**：结算页显示命中率（命中/发射）、受伤点数、最后一击来源（普通/快速/精英怪、掉出平台）
- ✅ **波次间补给**：选完词条回 1 血
- ✅ **难度曲线**：表驱动，第 1 波纯普通怪练手，第 3 波才出精英
- ✅ **重开体验**：结算页 `R` 零点击重开，标题页空格/回车直接开局

还要做：
- **手感复核**：把 `TuningPanel` 调出来的参数定稿写进 `PlayerStats.asset`，关掉调试面板也能玩
- **连败验证**：自己连续打 5 局，确认前三局输得明白、第五局能稳定推进

验收：找一个人（不用教）从打开到玩完一局，全程不需要问你。

### P2 · 内容深度（约 2 周，最花时间的一段）

- **敌人行为分化**（比加血量有效得多）：
  - ✅ 冲锋兵：高速冲撞、接触扣血，逼你跳
  - ✅ 炮台：原地不动、三连散射，逼你走位
  - ⬜ 分裂体：死亡裂成两个小的
  - ⬜ 飞行怪：无视平台直线追踪
  - ⬜ 护盾怪：正面免疫，必须绕后或跳射
- **Boss**：✅ 第 3 波换成单个 Boss，2 个招式循环（扇形弹幕 / 横向冲撞），0.5 秒变色蓄力预警，顶部血条
- **房间概念**：把"波次"换成 3 个手工房间（左进右出），清场开门，比"原地刷怪"更像游戏
- ✅ **词条扩容到 20 条**，并且**加入代价**：伤害 +1（射速 -15%）、移速 +25%（生命上限 -1）这类双效果卡，有取舍才有 build
- **词条稀有度**：普通/稀有，用颜色区分，抽取权重不同

验收：能说出两种完全不同的通关 build（例如"高射速散射流"和"高单发暴击流"）。

### P3 · 打磨（约 1.5 周）

- **背景与场景**：✅ 程序化渐变背景；🟡 视差层与贴图未做（仍是纯色块，但没有资源依赖）
- **受击/死亡动画**：✅ 敌人死亡先膨胀再淡出、玩家死亡爆散、命中闪白与震屏分级
- **屏幕过渡**：✅ 每波开场闪白；🟡 开局渐入未做
- **UI 统一**：🟡 配色已统一（深色面板 + 米色字 + 金色 hover），字体仍是默认字体
- **音乐**：✅ 程序生成 4 小节无缝循环（A 小调 i-VI-III-VII，低音 + 琶音 + 底鼓 + hi-hat），走独立 AudioSource
- **性能**：🟡 我方子弹已池化，敌方子弹与粒子仍 `Destroy`（数量小，暂未优化）
- **Boss 深度**：✅ 半血进入二阶段（预警 0.5→0.34s、扇形 7→9 发、冲撞加速、变红 + 狂暴提示）

验收：录 60 秒视频，不看文字也能知道在打什么、打中了没有。

### P4 · 发布（约 1 周）

- `Tools → Build WebGL (for itch.io)` 打包，压缩后上传 itch.io
- 页面：封面图、3 张截图、60–90 秒视频、操作说明、已知问题
- 版本打 tag（`v1.0.0`），README 换成玩家视角（怎么玩），技术复盘单独放 `Docs/`
- **找 5 个人试玩**，记录卡点，只修"阻断性"和"高频困惑"，不加新功能
- 发布后一周内收反馈，出 `v1.1` 小补丁

验收：一个陌生人打开链接，5 分钟内能自己玩起来。

## 三、明确不做（范围护栏）

写下来是为了以后能拒绝自己：

- ❌ 联机 / 排行榜服务器
- ❌ 多角色 / 多武器切换系统
- ❌ 程序化生成大地图、多层地图
- ❌ 云存档、账号系统
- ❌ 移动端触屏适配
- ❌ 多语言
- ❌ 自研引擎 / 换引擎重做

任何一条想加，先问：**它会让"完成"更近，还是更远？**

## 五、两条经验，值得写进复盘

1. **反馈强度不是越大越好，而是要有"预算"**。震动、停顿、粒子、音效都在抢玩家的注意力，同时全开等于全关。正确做法是分级：普通命中只给最小反馈，把强反馈留给"击杀"和"受伤"这种低频高价值事件。
2. **"做完"是一个范围问题，不是一个工作量问题**。这个项目烂尾的风险从来不是技术难度，而是"再想加一个系统"。所以先写死 v1.0 的定义和不做清单，比多写一千行代码有用。
